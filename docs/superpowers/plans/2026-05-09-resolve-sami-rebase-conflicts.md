# Resolve sami Octopus Merge Conflicts (post-upstream rebase) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve all conflicts in the four conflicted sami parents (`feat/cache-path-env-override`, `feat/npm-extended-sources`, `feat/session-sharding`, `feat/session-custom-id`) and the resulting sami merge, without losing any branch functionality, then verify with typecheck + tests + push.

**Architecture:** Octopus-merge fork pattern. Sami is a 10-parent merge over `dev` (`qkkymtuw`). All four conflicted branches were rebased onto current `dev`, which absorbed 243 upstream commits. Conflicts fall into two classes: (a) hand-written semantic merges where upstream changed lines adjacent to our branch's edits, and (b) generated artefact churn (`bun.lock`, `packages/sdk/openapi.json`, `packages/sdk/js/src/v2/gen/types.gen.ts`) which we **regenerate**, never hand-merge. We resolve each branch independently in a child commit (`jj new <branch>` → fix → `jj squash`), preserving change identity. Sami auto-rebases as parents become conflict-free; we add a sami-level lockfile regeneration as the final step so all branches' dependencies merge cleanly.

**Tech Stack:** jj (Jujutsu) version control, bun (lockfile + tests + typecheck), turbo (monorepo orchestration), TypeScript (`tsgo`), Drizzle ORM (sharding migrations), OpenAPI codegen (`packages/sdk/js/script/build.ts`).

## Conflict Inventory

### Hand-written code (must semantically merge)

1. **`packages/core/src/global.ts`** (in `feat/cache-path-env-override`) — branch replaces plain `cache,` field with a `get cache()` getter that reads `OPENCODE_CACHE_PATH` env. Upstream added `repos: path.join(data, "repos"),` immediately above. Resolution: keep upstream's `repos:` and the branch's `get cache()` getter.

2. **`packages/opencode/src/session/projectors.ts`** (in `feat/session-custom-id`) — branch wraps `db.insert(SessionTable)` in try/catch translating UNIQUE constraint failures to `Session.DuplicateIDError`. Upstream added a `db.update(WorkspaceTable).set({ time_used: ... })` call right after the insert. Resolution: try/catch only around the insert; the WorkspaceTable update runs unconditionally afterward.

3. **`packages/opencode/src/session/session.ts`** (in `feat/session-custom-id`) — branch adds `export const DuplicateIDError = NamedError.create(...)`. Upstream added `export type NotFound = InstanceType<typeof NotFoundError>` in the same spot. Resolution: keep both; `NotFound` first (matches upstream order), then `DuplicateIDError`.

4. **`packages/opencode/src/sync/index.ts`** (in `feat/session-sharding`) — most consequential. Branch refactors the `process` function body into helpers `transact()` / `apply()` / `emit()`. Upstream added `owner_id: options?.ownerID` to the `EventSequenceTable.values()` call inside the old inline body. Resolution: thread `ownerID` through the new helpers — `apply()` must accept and use it, and `process()` must pass `options.ownerID` to `apply`. Without this fix the branch silently drops owner-tracking on `OPENCODE_EXPERIMENTAL_WORKSPACES` events.

### Generated artefacts (regenerate; never hand-merge)

5. **`bun.lock`** in `feat/npm-extended-sources` (6 markers) and `feat/session-sharding` (also has lockfile drift but markers happen at sami level). Regenerate with `bun install` from a child of each branch.

6. **`packages/sdk/openapi.json`** + **`packages/sdk/js/src/v2/gen/types.gen.ts`** + **`packages/sdk/js/src/v2/gen/sdk.gen.ts`** in `feat/session-custom-id`. Regenerate with `./packages/sdk/js/script/build.ts`.

### Sami-level cross-branch conflicts

After all parents are clean, sami may still have `bun.lock` divergence (different branches add different deps) and `openapi.json` divergence. Strategy: regenerate both at the sami level as a final sweep.
